# 书树产品用户体验优化实施计划

**文档版本**: v1.0  
**创建日期**: 2026-06-07  
**项目负责人**: Senior PM  
**预计总工期**: 6-8 周（分3个阶段）

---

## 📋 执行摘要

### 核心问题
1. **导航结构混乱** - 书单/路径藏在二级菜单，wiki层级不一致
2. **信息架构不清晰** - 功能定位模糊，学习成本高
3. **交互流程繁琐** - 创建流程长，缺少快捷操作

### 优化目标
- **短期（2周）**: 统一导航结构，简化核心流程
- **中期（4周）**: 重新设计信息架构，建立内容管理体系
- **长期（6周+）**: 个性化推荐，社交增强，移动端优化

### 成功指标
- 新用户30秒内找到"书单"功能（当前需10+分钟）
- 书单/路径页面访问率提升300%（当前<5%）
- 创建书单流程从5步减少到2步
- 用户满意度评分从6/10提升到8/10

### P2.1 重新设计信息架构

**问题**: 功能定位模糊，用户不清楚何时使用哪个功能

**解决方案**:
- 重新定义核心功能模块的定位和关系
- 建立清晰的信息层级和导航逻辑
- 创建功能引导页（Onboarding）

**新的信息架构**:
```
书树 - 互动故事创作平台

1. 阅读（消费内容）
   ├─ 发现（推荐算法）
   ├─ 搜索
   ├─ 书单（我的书单 + 推荐书单）
   └─ 阅读路径（精选路径 + 创建路径）

2. 创作（生产内容）
   ├─ 写故事
   ├─ 管理分支
   ├─ 创建书单
   └─ 设计阅读路径

3. 社区（社交互动）
   ├─ 关注
   ├─ 通知
   └─ 个人资料

4. 知识（世界观设定）
   └─ Wiki（设定集）
```

### P2.3 引入智能推荐算法

**问题**: 当前推荐功能简单（仅按viewCount排序），缺少个性化

**解决方案**:
- 实现基于用户行为的推荐算法（协同过滤或内容相似度）
- 在"发现"页面显示个性化推荐
- A/B测试不同推荐策略

**任务列表**:

#### Task 2.3.1: 实现基于内容的推荐算法
- **文件**: `api/src/services/recommendationService.ts` (新建)
- **改动**: 
  - 创建推荐服务，基于以下因素计算相似度：
    - 标签相似度（TF-IDF）
    - 作者相似度（同一作者的作品）
    - 用户行为相似度（看过相同故事的用户还看了什么）
  - 返回推荐故事列表
- **验收标准**:
  - 推荐算法返回相关故事
  - 响应时间 <200ms
  - 推荐结果质量可接受（人工评估）
- **预估工时**: 10小时

#### Task 2.3.2: 更新"发现"页面使用推荐算法
- **文件**: `src/pages/discover/UniverseDiscoverPage.tsx`
- **改动**: 
  - "发现"Tab使用推荐API获取个性化推荐
  - "热门"Tab保留按viewCount排序
  - "最新"Tab按createdAt排序
- **验收标准**:
  - "发现"Tab显示个性化推荐
  - 新用户（无行为）显示热门内容
  - 老用户显示个性化推荐

#### Task 2.3.3: 添加推荐反馈机制（提升算法）

  - 故事卡片有"不感兴趣"按钮
  - 点击后该故事不再推荐给用户

## ⚠️ 风险和应对策略

### 风险1：开发资源不足
**风险**: 只有1名全栈工程师，无法同时推进Phase 1和Phase 2

**应对**: 
- 优先完成Phase 1（快速胜利，提升士气）
- Phase 2可以分阶段实施（先完成2.1新用户引导，再实施2.2和2.3）
- 考虑外包非核心功能（如多语言翻译）

### 风险2：推荐算法效果不好
**风险**: 协同过滤算法需要大量用户行为数据，新平台数据不足

**应对**:
- 先用基于内容的推荐（不依赖用户行为）
- 积累3个月数据后再切换到协同过滤
- A/B测试不同算法策略

### 风险3：现有用户不适应新导航
**风险**: 老用户习惯了旧导航，新导航可能导致困惑

**应对**:
- 上线前做用户调研（问卷或访谈）
- 上线时显示"导航更新提示"（可关闭）
- 保留旧导航作为选项（设置中切换）
