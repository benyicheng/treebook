# XS 交互一致性规范（UX Standards）

> 目标：全站“加载/空态/错误/重试/权限拦截/埋点/无障碍”一致，减少 `alert()` 与隐性失败。

## 1. 状态规范

### 1.1 加载（Loading）

- 首屏可交互 ≤ 1s（本地开发基线）
- 页面级加载：使用 Skeleton 或 Spinner；避免整页白屏
- 局部加载：按钮进入 `disabled + loading text`，避免重复提交

### 1.2 空态（Empty）

- 必须包含：一句说明 + 下一步行动（CTA）
- 如果空态由权限导致，应提示“需要权限/登录”而不是“暂无数据”

### 1.3 错误（Error）

- 错误消息必须可读（避免只 `console.error`）
- 必须提供：重试入口、返回入口
- 服务端错误优先展示 `message`，同时保留 `traceId` 供反馈

### 1.4 重试（Retry）

- 网络抖动：可自动重试（查询类 2 次以内）
- 用户操作型请求（mutation）：默认不自动重试，避免重复写入；如需重试必须有幂等策略

## 2. 权限拦截

- 前端：`PermissionGate` 仅用于 UI 层隐藏/禁用
- 后端：必须以 `authenticate` + `requirePermission` 做最终授权
- 无权限时：
  - `403`：提示缺少权限（可选提供申请入口）
  - 登录态缺失：重定向到登录页或弹出登录提示

## 3. 无障碍（A11y）与键盘可达性

### 3.1 通用要求

- 所有可点击元素必须是 `button/a`，并可通过键盘触发
- 对话框（Modal）必须：
  - 打开时 focus 移入
  - 关闭时 focus 回到触发点
  - 支持 Esc 关闭（若业务允许）
- 表单：
  - `label` 对应 input
  - 错误提示可被屏幕阅读器识别

### 3.2 焦点管理清单

- Tab 顺序自然
- 任何操作不会导致焦点丢失到 `body`
- “返回/取消/保存”键盘可操作

## 4. 埋点与反馈

- 每个关键路径至少埋点：
  - 登录成功/失败
  - 创建主线/章节/分支/书单/番外成功/失败
  - 权限被拒绝（403）
  - 全局错误边界触发
- 反馈信息最小集合：`traceId`、`userId`、`scene`（页面路径）、时间戳
